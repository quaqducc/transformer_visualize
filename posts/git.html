00Git là gì, và vì sao

Từng lưu file thành baocao_final_v2_thatsu_cuoi.docx? Git sinh ra để chấm dứt điều đó. Nó ghi lại lịch sử dự án: mỗi lần "lưu mốc" là một commit — một ảnh chụp toàn bộ dự án mà bạn luôn quay về được. Và bạn có thể tạo nhánh để thử nghiệm mà không phá bản chính, như những dòng thời gian song song.

01Commit & 3 vùng

Một thay đổi đi qua 3 nơi: Working Directory (bạn đang sửa) → git add → Staging (chọn cái sẽ lưu) → git commit → Repository (khắc vào lịch sử). Ẩn dụ giỏ hàng: add = bỏ món muốn mua vào giỏ; commit = thanh toán, in hoá đơn (commit có mã hash + thông điệp).

Chốt: commit chỉ chụp thứ đã ở Staging — nên phải add rồi mới commit.

02Dòng thời gian & HEAD

Mỗi commit trỏ về cha của nó, tạo thành chuỗi. HEAD là mũi tên "bạn đang đứng ở đâu" — thường trỏ tới nhánh hiện tại. git checkout <hash> đưa bạn về một commit cũ (trạng thái detached HEAD: xem được quá khứ nhưng đang đứng lệch khỏi nhánh).

Nhánh và HEAD chỉ là con trỏ — không phải bản sao thư mục. Đó là lý do Git nhẹ và nhanh.

03Nhánh

Một nhánh là tờ ghi chú dán lên một commit, và tự trượt theo mỗi khi bạn commit. git switch -c feature tạo & nhảy sang nhánh mới; commit trên đó làm đồ thị tách nhánh, còn main đứng yên. Rẽ nhánh gần như miễn phí vì chỉ tạo một con trỏ.

04Gộp nhánh — merge

Hai kiểu: fast-forward (nếu main chưa đi tiếp, gộp chỉ là đẩy con trỏ tới ngọn nhánh kia — lịch sử thẳng, không tạo commit) và 3-way (cả hai đã đi riêng → tạo một merge commit có 2 cha, nối hai dòng thời gian). Nếu hai bên sửa cùng một dòng, Git dừng lại báo xung đột để bạn chọn giữ gì.

merge giữ nguyên lịch sử của cả hai nhánh (có ngã ba).

05Rebase — viết lại cho thẳng

git rebase main nhấc các commit của nhánh bạn ra và phát lại chúng lên đỉnh của main → lịch sử thành một đường thẳng. Lưu ý: các commit được tạo lại với hash mới (không còn là commit cũ).

Aha: Merge = kể đúng chuyện đã xảy ra (có ngã ba). Rebase = kể lại cho gọn (một đường thẳng). Đẹp vs thật — tuỳ bạn chọn. Đừng rebase nhánh đã push/chia sẻ (viết lại lịch sử chung sẽ làm rối cả nhóm).

06Sửa sai — reset & revert

git reset tua con trỏ nhánh về commit khác. Ba mức khác nhau ở chỗ đụng tới 3 vùng: --soft giữ nguyên Staging + Working; --mixed (mặc định) bỏ Staging, giữ Working; --hard xoá sạch cả hai — mất thay đổi. git revert an toàn hơn: tạo một commit đảo ngược (không viết lại lịch sử) — hợp cho nhánh đã chia sẻ.

reset di chuyển lịch sử · revert thêm lịch sử.

07Làm việc nhóm — remote

origin là tên mặc định của repo trên server (GitHub). origin/main là "main trên server lần cuối mình thấy" (vẽ nét đứt). git push đẩy commit local lên; git pull = fetch (tải về) + merge. Nếu server có commit bạn chưa có, push bị từ chối → bạn pull rồi push lại.

Local và remote là hai bản đồng bộ thủ công — không tự động.
